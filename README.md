# 多源数据采集与质量校验

> 从多个数据源定时拉取行情数据，做清洗、去重、异常识别，落库后可供下游使用。
> 核心不只是"能拉到"，而是**能判断拉到的数据是不是真的**。

---

## 要解决的问题

批量采集数据时，最麻烦的不是拉取失败——失败会报错，看得见。
真正麻烦的是**拉到了，但数据是坏的**：

| 坏数据形态 | 表现 | 如果不处理 |
|---|---|---|
| **数据冻结** | 数值连续多期一模一样，但时间戳还在往前走 | 下游算出"零波动"，任何基于波动的计算全部失真 |
| **停更** | 某标的序列比同批其他标的落后好几天 | 用旧数据算当前状态，结论完全错 |
| **拼接** | 同一对象历史上换过一次源，前后两段硬接在一起 | 单期跳变 200%+，统计结果凭空翻倍 |
| **残留占位** | 已下线的对象仍在返回数据 | 拿僵尸数据做校验，校验形同虚设 |

这四种在公开数据源里都真实存在，而且**不会报错**。

---

## 核心设计

### 1. 三信号并集判定，互相不冗余

不是用单一规则判"数据死了"，而是三路独立信号取并集：

```python
FLAT_DAYS            = 10   # 连续 N 期数值【完全相同】⇒ 无有效变动。正常样本实测最大 1 期（余量 10x）
MAX_LAG_DAYS         = 1    # 序列落后池内最新数据日 > N 天 ⇒ 停更。正常样本实测恒 0 天
FIELD_LAG_SLACK_DAYS = 3    # 某字段更新滞后 > 池内中位 + N 天 ⇒ 该字段已废弃。实测中位≈0
SPLICE_MIN_FLAT      = 30   # 拼接检测：跳变前至少恒定 N 期才算「冻结段后复活」
SPLICE_JUMP          = 0.40 # 拼接检测：单期跳变绝对值阈值（实测最高 264.9%）
```

**关键点：每个阈值都有实测依据和余量说明。** 不是拍脑袋定 10 期，是"正常样本实测最大 1 期，取 10 期留 10 倍余量"。

这样阈值被质疑时能立刻拿出依据，而不是"我觉得 10 天差不多"。

### 2. 判据池内相对，不是绝对

"落后 3 天"这种绝对阈值放在一个整体都很慢的数据源上会误杀全池。
所以滞后判断用的是**池内中位数**做基准：

```python
def fr_lag_days(fr, asof_ts):
    """相对池内中位滞后算，不用绝对天数"""
```

### 3. 拼接检测单独一条路

价格跳变检测不是简单看"涨跌幅 > X%"，而是：
**先要求跳变前有一段长时间恒定（死段），再要求单日跳变超阈值**——
两条件同时成立才算"死段后复活"，避免把真实的暴涨暴跌误判。

## 代码摘录

### 连续平坦检测

```python
def trailing_flat(vals):
    """从尾部往回数，连续多少个值完全相同。
    用于识别「价格冻结」——有数据但没变化，比没数据更危险。"""
    if not vals:
        return 0
    last = vals[-1]
    n = 0
    for v in reversed(vals):
        if v == last:
            n += 1
        else:
            break
    return n
```

## 实际产出

分两块，别混。

### 1. 仓库里的 demo（`python quality.py`，直接能跑）

内置 4 个合成标的，覆盖「冻结 / 拼接 / 停更 / 健康」四种情形，跑出来是这样：

```
池内标的      : 4
判定有问题    : 3
FROZEN
    [FROZEN] 末尾连续 21 个值完全相同（阈值 10）
SPLICE
    [FROZEN] 末尾连续 60 个值完全相同（阈值 10）
    [SPLICE] 第 60 条出现 +400.0% 跳变，且跳变前长时间冻结
STALE
    [STALE ] 最后一条数据落后池内最新 30.0 天（阈值 1）
健康标的: HEALTHY
```

demo 是为了让人 3 秒看到判定逻辑，不带真实数据。

### 2. 真实项目里跑出来的结果（不在仓库里，仅作说明）

同一套逻辑接在一个 166 标的的池子上：

```
池内标的      : 166
判定为死数据  : 45   (27.1%)
  ├ 价格冻结  : 38
  ├ 序列停更  : 5
  └ 字段废弃  : 11   （有重叠）
检测到拼接    : 1    单日跳变 +264.9%
```

**这 45 个标的如果不过滤，会让下游统计出现系统性偏差。**

这也是这套检查存在的理由：**27% 的标的是坏的，而且没有一个会报错。**

## 怎么用

```bash
python quality.py            # 用内置合成数据跑演示，直接看检测效果

```

零第三方依赖，只用标准库。`quality.py` 里的检测函数可以直接 import 到你自己的管道里：

```python
from quality import trailing_flat, splices, check_series
```

内置演示数据构造了 4 个标的：一个健康、一个冻结、一个停更、一个拼接。

## 局限（写出来是为了可信）

1. 阈值基于单一市场类型的实测，换到别的数据源（比如电商价格、天气）需要重新校准
2. 拼接检测只处理"长时间恒定后跳变"，处理不了"缓慢漂移"
3. 没有做跨源交叉校验（比如两个源对同一标的的报价对比），这是 v0.2 的计划
