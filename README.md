# 多源数据采集与质量校验

> 从多个数据源定时拉取行情数据，做清洗、去重、异常识别，落库后可供下游使用。
> 核心不只是"能拉到"，而是**能判断拉到的数据是不是真的**。

---

## 要解决的问题

批量采集数据时，最麻烦的不是拉取失败——失败会报错，看得见。
真正麻烦的是**拉到了，但数据是坏的**：

| 坏数据形态 | 表现 | 如果不处理 |
|---|---|---|
| **数据冻结** | 价格连续多日一模一样，但时间戳还在往前走 | 下游算出"零波动"，任何基于波动的策略全部失真 |
| **停更** | 某标的的价格序列比同批其他标的落后好几天 | 用旧价格算当前持仓，盈亏完全错 |
| **拼接** | 同一标的历史上换过一次，前后两段数据硬接在一起 | 单日跳变 200%+，回测收益凭空翻倍 |
| **退市残留** | 已下架的标的仍在返回报价 | 拿僵尸报价算持仓，风控形同虚设 |

这四种在公开数据源里都真实存在，而且**不会报错**。

---

## 核心设计

### 1. 三信号并集判定，互相不冗余

不是用单一规则判"数据死了"，而是三路独立信号取并集：

```python
DEAD_FLAT_DAYS = 10      # 连续 N 日收盘【完全相同】⇒ 无成交。活币实测最大 1 天（余量 10x）
MAX_KL_LAG_DAYS = 1      # 价格序列落后池内最新数据日 > N 天 ⇒ 停更。活币实测恒 0 天
FR_LAG_SLACK_DAYS = 3    # 费率滞后 > 池内中位滞后 + N 天 ⇒ 费率已废弃。活币实测中位≈0
SPLICE_MIN_FLAT = 30     # 拼接检测：跳变前至少恒定 N 天才算「死段后复活」
SPLICE_JUMP = 0.40       # 拼接检测：单日跳变绝对值阈值（实测最高 +264.9%）
```

**关键点：每个阈值都有实测依据和余量说明。** 不是拍脑袋定 10 天，是"活币实测最大 1 天，取 10 天留 10 倍余量"。

这样阈值被质疑时能立刻拿出依据，而不是"我觉得 10 天差不多"。

### 2. 判据池内相对，不是绝对

"落后 3 天"这种绝对阈值放在一个整体都很慢的数据源上会误杀全池。
所以滞后判断用的是**池内中位数**做基准：

```python

    """相对池内中位滞后算，不用绝对天数"""
```

### 3. 拼接检测单独一条路

价格跳变检测不是简单看"涨跌幅 > X%"，而是：
**先要求跳变前有一段长时间恒定（死段），再要求单日跳变超阈值**——
两条件同时成立才算"死段后复活"，避免把真实的暴涨暴跌误判。

## 代码摘录

### 连续平坦检测

```python
def trailing_flat(vals):
    """从尾部往回数，连续多少个值完全相同。
    用于识别「价格冻结」——有数据但没变化，比没数据更危险。"""
    if not vals:
        return 0
    last = vals[-1]
    n = 0
    for v in reversed(vals):
        if v == last:
            n += 1
        else:
            break
    return n
```

## 实际产出

跑一次全池扫描，输出：

```
池内标的      : 166
判定为死数据  : 45   (27.1%)
  ├ 价格冻结  : 38
  ├ 序列停更  : 5
  └ 费率废弃  : 11   （有重叠）
检测到拼接    : 1    单日跳变 +264.9%
```

**这 45 个标的如果不过滤，会让下游统计出现系统性偏差。**


---

## 局限（写出来是为了可信）

1. 阈值基于单一市场类型的实测，换到别的数据源（比如电商价格、天气）需要重新校准
2. 拼接检测只处理"长时间恒定后跳变"，处理不了"缓慢漂移"
3. 没有做跨源交叉校验（比如两个源对同一标的的报价对比），这是 v0.2 的计划
